# اتصال هدهد به موتور اصلی

نسخهٔ رابط اکنون به Django موجود در `backend` متصل است. مدل پیش‌فرض انتخاب‌شده `gpt-5-mini` است. بدون کلید، موتور داده‌محور همان بک‌اند پاسخ می‌دهد و وضعیت رابط این تفاوت را نشان می‌دهد؛ تست با ارائه‌دهندهٔ شبیه‌سازی‌شده به معنی تست زندهٔ GPT نیست.

## اجرا

در PowerShell از `the repository root`:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\configure-model.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Production
```

کلید در ورودی مخفی گرفته و در `.env` ذخیره می‌شود. برای ارائه‌دهندهٔ دیگر `configure-model.ps1 -BaseUrl https://provider.example/v1` را اجرا کنید. کلید به فرانت، پاسخ API یا فایل‌های build وارد نمی‌شود. پس از تغییر تنظیمات سرور را راه‌اندازی مجدد کنید.

در Git Bash:

```bash
cd /path/to/HodHod
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./configure-model.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ./start.ps1 -Production
```

آدرس رابط `http://127.0.0.1:5173`، API کاتالوگ `8787` و موتور گفتگو `8790` است. راه‌انداز هر سه سرویس را مدیریت می‌کند؛ Ctrl+C سرویس‌های متعلق به همان اجرا را متوقف می‌کند. در اولین اجرا نصب وابستگی‌ها اینترنت می‌خواهد. اجرای تکراری واردسازی را با امضای منبع بررسی و رد می‌کند.

## مسیر واقعی درخواست

`ChatComposer → BackendAgentAdapter → /api/brain/dispatch/ → Django workspace → llm.chat → tools → canonical source IDs → registered UI`.

ابزارهای جستجو، سؤال تکمیلی، فیلتر، رتبه‌بندی، فروشندگان، مقایسه و برنامهٔ خرید موتور اصلی حفظ شده‌اند. ابزار `render_workspace` انتخاب نقشه، مقایسهٔ کالا/فروشنده، برنامهٔ مراجعه و خرید فوری را به مدل می‌دهد. مختصات و کالاهای روی صفحه از دادهٔ سرور به مدل معرفی می‌شوند. برنامهٔ خرید فوری از سرویس موجود برای ساعت کاری و مسیر استفاده می‌کند. زمان مسیر تنها در صورت پاسخ واقعی مسیریاب نمایش داده می‌شود.

عکس از طریق `/api/brain/image/` به مدل پیکربندی‌شده فرستاده می‌شود. عبارت شناسایی‌شده پیش از جستجو قابل ویرایش است؛ نتیجهٔ مدل تصویر به عنوان قیمت یا موجودی استفاده نمی‌شود. خود برنامه عکس را نگه نمی‌دارد. تایپ صوتی از قابلیت واقعی گفتار مرورگر استفاده می‌کند؛ تبدیل فایل صوتی آپلودشده هنوز ارائه‌دهنده ندارد.

حالت‌های آزمایشی قبلی و `/showcase` حفظ شده‌اند؛ `/?mode=demo` اجرای قابل تکرار و `/?mode=brain` موتور اصلی را انتخاب می‌کند. وضعیت پیش‌فرض موتور اصلی است.

## داده و نشست

هر سه CSV اصلی دست‌نخورده‌اند. کاتالوگ اصلی در `.local/torob.sqlite` و نسخهٔ ORM موتور در `.local/brain.sqlite3` است: ۲۲۵۹۰۳ کالا، ۳۳۱۵۰۶ آفر، ۶۴۷۶ فروشگاه. تصاویر و اطلاعات کارت‌ها از همان payload منبع برمی‌گردند؛ قیمت نامعلوم حفظ می‌شود. دادهٔ مسابقه موجودی زنده نیست؛ شماره‌های مصنوعی در تماس استفاده نمی‌شوند.

SQLite/FTS5 برای اجرای مستقل محلی اضافه شده است؛ تنظیمات PostgreSQL پروژهٔ اصلی موجود است. کلید نشست سرور پایدار و محلی است. CandidateSet با هش ترکیب نشست HttpOnly مرورگر و شناسهٔ گفتگو جدا می‌شود. CSRF، اعتبارسنجی شکل درخواست، allowlist ابزار و کامپوننت، شناسهٔ درخواست، حذف پاسخ قدیمی و cache تکرار درخواست فعال‌اند. تاریخچه و انتخاب‌ها در IndexedDB می‌مانند. پاک‌کردن کوکی، دسترسی به CandidateSet قدیمی را قطع می‌کند؛ کاتالوگ همچنان قابل بازیابی است.

## بررسی

```powershell
.local\brain-venv\Scripts\python.exe backend/manage.py test shopping --settings=config.test_settings --noinput
.local\brain-venv\Scripts\python.exe scripts/test_brain_integration.py
pnpm build
pnpm test
pnpm test:e2e
.local\brain-venv\Scripts\python.exe scripts/verify_model.py
```

آزمون‌های بک‌اند شامل جداسازی نشست، CSRF، رد شناسهٔ جعلی، عدم افشای کلید، محدودیت عکس و حلقهٔ ابزار با SDK رسمی روی یک ارائه‌دهندهٔ محلی شبیه‌سازی‌شده هستند. اسکریپت integration با دیتاست کامل، برابری تمام اطلاعات برگشتی با منبع، گفتگو، سؤال تکمیلی، صفحه‌بندی، بودجه، نقشه، مقایسه، مراجعه و خرید فوری را بررسی می‌کند. آزمون مرورگر مسیر واقعی UI تا Django و حفظ گفتگو پس از reload را اجرا می‌کند.

این راه‌انداز برای اجرای محلی است. سرویس‌های عمومی نقشه و مسیریابی به اینترنت وابسته‌اند و در خطا زمان جعلی جایگزین نمی‌شود. دقت گفتگوی آزاد و عکس با مدل واقعی تنها پس از تنظیم کلید قابل تأیید است.

نتیجهٔ بررسی ۲۳ اکتبر ۲۰۲۶: build و TypeScript موفق؛ ۵۴ آزمون فرانت، ۱۸ آزمون Django، ۱۱ آزمون دیتاست، ۴ آزمون مسیریابی، ۵ آزمون خرید فوری و ۲۳ آزمون مرورگر روی نسخهٔ تولیدی، همگی موفق بودند (۱۱۵ آزمون؛ بدون skip). بررسی مستقل اتصال به دیتاست کامل نیز موفق بود. راه‌انداز یکپارچه اجرا و خروج سرویس‌های متعلق به آن بررسی شد. کلید مدل در زمان تحویل تنظیم نشده بود؛ آزمون زندهٔ مدل با وضعیت NOT RUN ثبت شد. حلقهٔ tool calling با SDK رسمی و سرور سازگار شبیه‌سازی‌شده آزمایش شد.

`verify_model.py` پس از تنظیم کلید یک درخواست محدود واقعی به ارائه‌دهنده می‌فرستد، فراخوانی ابزار جست‌وجو و بازگشت کارت‌های منبع را بررسی می‌کند. بدون کلید با وضعیت NOT RUN تمام می‌شود.
