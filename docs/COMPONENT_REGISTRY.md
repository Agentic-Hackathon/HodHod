# Component registry and gallery

`shopping_mission` → `ShoppingMissionWorkspace` adds the urgent purchase flow with optional validated `props.mission` intent settings, arrival-based recommendations, recovery reports and a separate exploratory map. See [URGENT_SHOPPING.md](URGENT_SHOPPING.md) for its input contract and evidence rules.

`src/generative-ui/registry.tsx` is the allowlist; `schema.ts` validates prop keys, IDs, limits and envelope version. `/gallery` is a free interactive preview of every block with actual loaded records. `/showcase` supplies valid multi-offer data for deep views; navigate there first for populated comparison/visit examples. Closed gallery sections avoid cramming all widgets on one screen.

Every wire block has `{id, type, props}`. The example IDs below are placeholders; replace them with `/api/scenarios` or actual entity IDs. Common block shape: `{"id":"stable-slot","type":"product_grid","props":{"productIds":["product_example"]}}`.

Image and voice controls are composed in the chat input rather than independently registered canvas blocks because they own transient File/browser permission state. Registry entries are the renderable domain blocks; leaf components receive typed factual props and callbacks. All cards have hover/focus/selection states; loading/error exist at query boundaries. Modal focus trapping, Escape and focus restore are centralized in Dialog. Button/IconButton/Badge/ProductImage/EmptyState provide consistent primitive behavior. Light/dark and reduced-motion variants apply globally.

## Scope of v1

MultiStoreItinerary is intentionally deferred as optional progressive enhancement. Category hierarchy is not fabricated. Seller comparison is separate from product comparison. The map's synchronized cards represent shops in the visible result page, never all shops in Tehran. Live availability, message sending, actual image recognition, a self-hosted STT backend and agent reasoning belong to external adapters and are explicitly labeled unavailable until connected.
