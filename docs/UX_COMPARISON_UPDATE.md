# Unified comparison and geographic radius

Implemented in the existing local application; CSV sources and the read-only index are unchanged.

- Comparison now contains product specifications or same-product seller comparison, a geographic shop map, distance cards, the Pareto frontier and priority-based recommendations in one workspace. All sections use the same offer scope. Products pinned across result pages remain available from the persisted entity cache. Legacy `decision` scenes open this shared workspace; there is no separate decision navigation tab.
- Map markers identify the corresponding numbered shops in the list; nearby markers group into an accessible shop chooser to avoid overlap. Choosing a map shop updates the shared selected shop/offer. The blue marker is the chosen user origin. Shops missing coordinates remain in the list. Walking/driving route previews use the existing real routing gateway on explicit request. Straight-line distances and the price/distance Pareto are explicitly labeled as such; travel times are not substituted for geographic distance.
- Search radius is a 96-segment geodesic polygon using the same 6371 km sphere as the dataset search, rather than a circle with a fixed pixel size. It appears in the live draft filter map, the main nearby map and nearby comparison maps. Draft edits do not change canonical search until submission.
- Price status has three choices: all, known prices, unknown prices. The API applies the status to the product EXISTS condition, counts, paginated results and returned offers. Unknown-only filtering clears numeric budget restrictions; choosing a budget switches back to priced offers. Mixed-price products appear if at least one matching offer exists, and only matching offers are returned by search. Null prices remain null.
- The comparison tray displays each selected product's image, title and a named remove action. It scrolls horizontally on narrow screens and occupies its own layout space rather than covering the comparison content.
- Agents can emit the new allowlisted `comparison_workspace` block with actual `productIds` or `offerIds` and optional `shopIds`; entity IDs are resolved through the existing safe registry. Existing individual blocks remain compatible. Requests include optional `filters.priceStatus` (`all`, `known`, `unknown`); older persisted sessions default to all.

New browser coverage exercises real-dataset filtering/persistence, map origin/radius changes, the shared comparison scope and marker picker, purchase route preview, accessibility, tray identity/removal, and desktop/tablet/mobile layout without overlap. Radius unit checks verify every polygon vertex at all six offered radii and three latitudes. Dataset integration checks compare totals with SQL and check matching offers across pages. Browser routing is mocked; external map tiles can be unavailable and the UI preserves its geographic overlays and shop list.
